## 一、背景与目标

武汉大学天文协会即将开展科普答题活动：由协会科普负责人「督师」每天出题，群成员作答、计分。

**产品目标**

1. 洛书 bot 新增人格「**督师**」，作为活动期间的发声人格；
2. 每天定时在群内发布一道「**图文选择题**」；
3. 成员**私聊**机器人作答，避免群内互相剧透；
4. 机器人**自动判分、自动累计**，并同步到**在线表格**供实时查看；
5. 全流程尽量自动化，管理员只在「录题」和「异常处理」时介入。

**设计原则**

- **题目内容由人工提供，AI 不生成天文题目。** 本地模型只有 4B，生成天文知识题有编造风险，准确性无法保证；AI 只负责发布、判分、统计。
- 判分规则确定、可追溯、可申诉。
- 云端不可用时自动降级：本地先存，恢复后补传，不丢数据。

## 二、角色设定：督师

在 `src/plugins/personas.py` 的 `PERSONAS` 中新增人设「督师」。

| 维度 | 设定 |
|---|---|
| 身份 | 武汉大学天文协会成员，负责科普 |
| 性格 | 对天文有真热情；讲得清楚、耐得住"冷问题"；鼓励为主，答错不嘲讽；不端着，但也不乱开玩笑 |
| 语言 | 比日常口吻更"讲得明白"一点，喜欢用一次生活化的类比解释概念；不堆术语，术语出现时随手解释一句 |
| 边界 | 不臆造数据与结论；不确定就直说"这个我也不太确定，回头查证" |

**督师人格与答题功能的关系（建议）**

- **人格**只负责"说话的口吻"：发布题目的导语、判分后的鼓励、公布答案时的讲解；
- **答题功能**独立成一个插件，**不绑死在人格上**（否则 `/切换` 一下功能就失效）；活动期间只要把默认人格切到「督师」即可。
- **每题解析建议由你提供**（题库里的"解析"字段），AI 不负责讲天文知识 —— 这是本活动科普价值的关键，也是准确性最容易翻车的地方。

## 四、功能详述

### F1 题库管理

**每道题的字段**

| 字段 | 必填 | 说明 |
|---|---|---|
| 题号 | 自动 | 形如 `Q0001`，按录入顺序递增 |
| 计划发布日期 | 是 | 决定哪一天自动发出 |
| 题干 | 是 | 文字 |
| 图片 | 否 | 默认 1 张（预留多张） |
| 选项 | 是 | 支持 2~6 个（A~F），默认 4 个 |
| 正确答案 | 是 | 单个字母（预留多选） |
| 分值 | 否 | 默认 1 分 |
| 解析 | 否 | 公布答案时一并发出，用于科普 |

**录入方式（两种，都做）**

1. `/出题` —— 分步引导，管理员**私聊机器人**依次发：题干 → 图片 → 选项 → 正确答案 → 解析 → 指定发布日期；支持「上一步 / 取消」。
2. **批量导入** —— 你在活动前把题目整理好（Excel 或 JSON）发我，我转成标准格式一次性导入 N 天的题。**推荐用这种方式，最省事。**

**管理命令**

| 命令 | 说明 |
|---|---|
| `/题库` | 列出待发 / 已发题目及排期 |
| `/预览 <题号>` | 只发给管理员自己看，确认真实效果 |
| `/改题 <题号>` | 修改指定字段 |
| `/删题 <题号>` | 删除（需二次确认） |

**图片处理（关键）**

> QQ / NapCat 给到的图片地址**会过期**，如果不落地保存，活动后期题目图会变成空白。

- 收到图片时立即下载到本地 `data/quiz/images/Q0001.jpg`；
- 发布时用**本地文件**重发，不依赖原链接；
- 如需长期归档或跨机使用，再考虑上传图床，但本地一份是必须的。

---

### F2 定时发布

- 每天固定时间（如 **20:00**，可配置）向**目标群**发布当天题目；
- **多群同一时刻发送**，保证所有人同时看到题；
- 发布内容示例：

  ```
  【督师 · 天文科普 Q0001】
  ＜题干文字＞
  ＜题目图片＞
  A. …   B. …   C. …   D. …

  作答方式：私聊我发送  A / B / C / D  （或 /答 A）
  截止时间：明天 20:00
  ```

- **兜底机制（必须有）**
  - 当天没有排期题目 → **主动私聊告警给管理员**，不静默不发；
  - 机器人 / 电脑重启错过时间 → 支持补发（misfire 容忍）；
  - `/发题` 手动立即发布；`/发题 Q0003` 指定补发某题。
- **活动周期**：可设置开始 / 结束日期，到期自动停止发题。

---

### F3 私聊答题

- 群里**只发题**，成员**私聊机器人**作答；
- 提交格式（三种都支持）：

  | 写法 | 场景 |
  |---|---|
  | `/答 A` | 当天只有 1 道进行中的题 |
  | `/答 Q0001 A` | 同时有多题时指定题号 |
  | 直接发 `A` | 当且仅当有且仅有 1 道进行中的题 |

- **校验与反馈**

  | 情况 | 处理 |
  |---|---|
  | 题目不存在 | 提示"没有这道题"，不记分 |
  | 已截止 | 提示"这题已经结束啦"，不记分（可配置为迟交计分） |
  | 格式不对 | 提示正确写法，不记分 |
  | 重复提交 | **只记第一次**（避免刷分），提示"你已经答过啦" |
  | 提交成功 | 立即私聊回执："已记录 Q0001 → A" |

- **是否即时告知对错**：**建议不即时告知**（否则有人可以用小号反复试答案），改为截止后统一公布。可配置。
- **不误判**：没有进行中的题目时，成员私聊发的消息走正常聊天（督师人格回应），不会被当成答案。

---

### F4 自动判分

- 选择题：提交答案与正确答案比对，正确得该题分值（默认 1 分），错误 0 分；
- **记录字段**：题号、QQ、昵称、提交答案、是否正确、得分、提交时间；
- **幂等**：同一条 `message_id` 重复推送不得重复计分（OneBot 实现偶有重推）。

---

### F5 排行榜与个人成绩

| 命令 | 权限 | 说明 |
|---|---|---|
| `/排行` | 所有人（可配置） | 当前总分 Top 10 |
| `/我的成绩` | 本人 | 私聊查看自己的总分、答对数、正确率 |
| `/查分 <@某人>` | 管理员 | 逐题明细 |

- **排名规则**（需你确认）：总分降序 → 答对数降序 → 首次提交时间**早者优先**；
- **口径公示**：活动开始前在群公告里固定写明计分规则，避免争议。

---

### F6 云端保存（在线可看的分数表）

- **载体**：腾讯文档**在线表格**
  - 表一（汇总）：昵称、总分、答对数、参与天数、最近提交时间 —— 一行一人；
  - 表二（明细）：题号、昵称、提交答案、是否正确、得分、提交时间 —— 一行一次作答。
- **同步时机**：每轮答题结算后增量写入；支持 `/同步` 手动触发；
- **降级策略**：同步失败 → 本地 JSON 先存并标记"待同步"，恢复后自动补传，同时通知管理员；
- **前提**：需要你提供腾讯文档信息（用哪个账号、表格放哪、由你建还是我建）；
- **隐私**：表格建议**不写 QQ 号**；权限建议"管理员可编辑、成员只读"。

---

### F7 截止与公布答案

- 每题有截止时间（默认：**次日发新题时截止上一题**，或当天 23:59，可配置）；
- 截止后自动在群里公布：**正确答案 + 你的解析 + 本题得分情况**（可选：谁答对 / 多少人答对）；
- 截止后的提交默认不记分（可配置为迟交计半分）。

---

### F8 权限与开关

| 操作 | 权限要求 |
|---|---|
| 出题 / 改题 / 删题 / 发题 / 公布答案 | 机器人管理员（`SUPERUSERS`） |
| 查分 / 调分 / 导出 / 云端同步 / 答题设置 | 机器人管理员 |
| 答题 | 群成员（含管理员） |
| 看排行榜 | 所有人（可配置仅管理员） |
| 功能开关 | `/功能 关闭 答题`，群管理员即可，**按群隔离** |

## 五、技术方案（落地细节）

**复用现有机制**（洛书 bot 已具备）

| 能力 | 现有实现 | 复用方式 |
|---|---|---|
| 权限分级 | `core.get_role()`，4 级（群员 / 群管 / 群主 / 超级管理员） | 直接调用 |
| 按群功能开关 | `features.guard("key")` + `TOGGLEABLE` 注册表 | 新增 `{"key":"quiz","name":"科普答题"}` |
| 数据存储 | `core.JsonStore`（按群隔离、原子写入、崩溃安全） | 直接复用 |
| 定时任务 | `nonebot_plugin_apscheduler`，`notice.py` 已有 `scheduler.scheduled_job("cron", ...)` 先例 | 照抄写法 |
| 命令日志 / 统计 | `core.log_command()`、`stats.py` 自动收录 | 自动生效 |
| 帮助菜单 | `help_menu.py` 的 `FEATURES` 注册表 | 新增分类「科普答题」+ 条目 |
| 私聊推送 | `bot.send_private_msg()` | 发送回执 / 告警 |

**建议新增文件**

```
src/plugins/quiz.py            # 主插件：出题 / 发题 / 答题 / 判分 / 排行
src/plugins/quiz_cloud.py      # 腾讯文档同步（可拆可合）
data/quiz/questions.json       # 题库
data/quiz/answers.json         # 答题记录
data/quiz/config.json          # 发布时间 / 截止 / 分值 / 目标群 / 活动周期
data/quiz/images/              # 题目图片（Q0001.jpg）
```

**命令总表**

| 命令 | 权限 | 作用 |
|---|---|---|
| `/出题` | 管理员 | 分步录入新题 |
| `/题库` | 管理员 | 查看题库与排期 |
| `/预览 <题号>` | 管理员 | 预览发布效果 |
| `/改题` `/删题` | 管理员 | 修改 / 删除题目 |
| `/发题 [题号]` | 管理员 | 立即发布 / 补发 |
| `/答案 [题号]` | 管理员 | 提前公布答案 |
| `/答 <题号> <答案>` | 所有人 | 私聊作答 |
| `/排行` | 所有人 | 查看排行榜 |
| `/我的成绩` | 本人 | 私聊查自己的成绩 |
| `/查分 <@某人>` | 管理员 | 查某人的逐题明细 |
| `/调分 <@某人> <分>` | 管理员 | 人工改分（留痕） |
| `/答题设置` | 管理员 | 发布时间、截止、分值、目标群 |
| `/同步` | 管理员 | 手动同步云端 |
| `/导出` | 管理员 | 导出成绩表 |
| `/答题总览` | 管理员 | 今日发了没 / 多少人答 / 正确率 |

**⚠️ 与现有插件的交互（容易踩坑，务必注意）**

1. **私聊答题 vs AI 对话**
   `ai_chat` 的 `chat` 匹配器是 `priority=97, block=True`，且对私聊消息同样生效。
   答题插件必须用**更低优先级**（如 90），并且**只在"确有进行中的题目 + 文本像答案"时才命中** ——
   否则要么抢走正常聊天，要么答案被聊天插件吃掉。
2. **群内命令**：答题管理命令用 `on_command`，与现有命令不冲突。
3. **冷冲突**：`core.check_cooldown` 默认 3 秒，连续答两题会被挡。答题需单独设更短冷却。
4. **敏感词**：题干与答案同样过 `security` 过滤，避免题目里混入敏感词导致**发不出去**。
5. **并发**：多人同时私聊提交答案，需复用 `core` 的锁机制，避免分数写坏。

## 六、你没提到、但建议加上的（12 条）

1. **图片必须落盘** —— QQ 图片链接会过期，不下载的话活动后期题目图会变空白。
2. **防剧透只解决了一半** —— 私聊答题防住了"看到别人答案"，但群里仍会有人公开讨论/晒答案。可选：答题期内自动撤回含正确答案的消息（风险高，需谨慎评估）。
3. **不要即时公布对错** —— 否则可以用小号反复试答案刷分。
4. **一人一题一答** —— 首次为准。小号刷分技术上防不住，建议改用"事前报名登记 + 人工抽查"。
5. **断线补偿** —— 机器人/电脑重启会错过定时发题，需要 misfire 容忍与补发。
6. **题库断档告警** —— 排期空了要主动通知管理员，不能静默不发。
7. **每题配科普解析** —— 这是天文协会活动真正的价值所在，也是准确性最需要你把关的地方。
8. **成绩申诉机制** —— 给一个申诉窗口（如公布后 24 小时内联系管理员），人工调分需留痕。
9. **隐私处理** —— 分数表用昵称不用 QQ 号；群内排行榜是否公开由你定。
10. **活动结束流程** —— 设结束日期、停止发题、导出最终成绩存档。
11. **主持人视角 `/答题总览`** —— 让管理员一眼看到"今天发了没 / 多少人答 / 正确率多少"。
12. **预览与撤回** —— 发题前 `/预览` 确认真实效果；发错后 `/撤回` 重发。

## 七、分阶段实施建议

| 阶段 | 内容 | 说明 |
|---|---|---|
| **P0** | 题库录入 + 手动发题 + 私聊答题 + 自动判分 + `/排行`（本地存储） | 最小可用，先跑通闭环 |
| **P1** | 定时自动发题 + 截止公布答案 + 提醒 | 省去每天手动操作 |
| **P2** | 腾讯文档云端同步 + 导出 + 人工调分 | 需要你的腾讯文档就位 |
| **P3** | 督师发布导语/点评、`/答题总览`、申诉处理 | 体验优化 |

建议 **P0 + P1 在活动开始前完成**；P2 视腾讯文档的准备情况并行推进。

## 八、需要你确认的问题

1. 活动在**几个群**进行？是同一个题发给所有群，还是各群不同题？
2. 每天**几点**发题？截止时间怎么定？
3. 每题**分值**、总分、计分规则？
4. 答错是 0 分吗？**迟交**是否计分？
5. **排行榜**是否对所有人公开？显示昵称还是 QQ 号？
6. **腾讯文档**：用哪个账号？表格由你建还是我建？权限怎么设？
7. 题型只要**单选**，还是也要**判断题 / 多选 / 填空**？
8. 督师的语气定位：偏"亲切学长"还是偏"严谨助教"？
9. **题目解析**由你提供，还是允许我用 AI 生成？（**建议你提供**）
10. 每天是**一道题**还是**多道题**？
11. 题目来源是纯自出，还是需要我帮忙找天文素材？
12. 活动**起止日期**定了吗？
